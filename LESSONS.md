# LESSONS — process rules for running this project

Each rule is one line, with its evidence in brackets. Pruned at G7 (2026-10-28) after a fresh-agent "stop doing / worked well" review (reviews/lessons_review_g7.md); previous prune M2.

1. Check data access (APIs, bot walls, licences) before planning around a source, and give every "if obtainable" input a deadline and a recorded fate. [DepMap portal's Cloudflare check found in the first 5 minutes; the K562 CRISPRi anchor and CORUM lapsed with no recorded decision (D28).]
2. Lock the test split and commit it before any modelling. [104 patient-sharing lines made the split non-trivial; locked at 3834bc9 on day 1, it kept every later choice blind and the G4 reviewer verified it from one commit.]
3. Even "calibration" probes go through the shared evaluation code, or are not run. [The fold-0 probe tuned λ on validation and imputed with validation lines; its numbers had to be quarantined (tree 1.3).]
4. Review a design with one parallel panel of distinct expertise, then a single fresh reviewer plus targeted reviewers for new risks only. [R1's 7 reviewers found non-overlapping problems; R2's same 7 returned mostly "minor"; R3's one fresh reviewer found unset thresholds and inconsistent gene classes.]
5. Accept a review item only with an owner and a check, verify it at the next gate, and decline the rest explicitly; "accepted but not done" costs more credibility than "declined". [174 accepted items ended 31 partial and 9 not implemented, one claimed done when it was not (R1-BI-17), found only by the retrospective check (D28).]
6. A process promise is a check that a gate script enforces, or it is cut; prose-only safeguards lapse. [Guard, gate.py and check_report_numbers all ran and let reviewers verify G4/G6 from git alone; the scope ledger, implementation check, G5 gate and status block promised in DESIGN §9 were only reconstructed at G7 (D28).]
7. Before freezing a decision rule, dry-run it on non-blinded inputs: every verdict branch reachable, every condition non-vacuous, every named gene, line and anchor present; fix the rule, don't reword the result. [The freeze reviewer's "ratio condition vacuous" flag was declined; "fails" proved unreachable (D21e) and "transfers" had to be qualified post hoc (D27); POU5F1 was absent from the hPSC screen and only 4 of "7" EC lines were dev (D20d).]
8. Cross-check metrics with an independent agent's own code once, before freezing evaluation; afterwards spend reviewer effort mainly on red-team questions. [G0 cross-check matched to 6 decimals and found 3 guard gaps; later full re-implementations found 0 discrepancies (G4 ≤ 2.1e-8, G6 ≤ 4.9e-5 rounding), while red-team questions changed D16 and the G6 wording (D27).]
9. Before calling an arm negative, view it a second cheap way: leave-one-out beside add-one, the published simple method beside the pre-registered variant, a scale scan of any correction. [Add-one modalities all hurt but LOO showed C +0.009, E +0.021 (D15); the B1-residual target cost 0.008 vs raw ridge (D14); M2/M3 at full scale +0.0034/+0.0018, averaged +0.0094 (D23).]
10. Set a control's expected bound by simulating the control under the null before the run. [m5_ctl_perm weight 0.041 vs a 0.01 bound because one shared permutation scales with 1/√(n lines) (D23b); two permutation controls missed their bands (D20b); all had to be "accepted as interpreted".]
11. Build anything that depends on the final model (tiers, characterisation, evaluation integration, dry runs) only after model selection closes, or key it by model id. [Tiers frozen on m1 then re-frozen on m5_avg (2410d36 → 6c5e004); characterisation ran 3× (5b0ad1b, fa5dd40, e935165); the first G4 dry run was deleted (4c9118c) and G4/G6/predict.py re-integrated (593ead7–aed0b7e).]
12. Parallel tracks get their own files and ID ranges, and shared append-only logs get a file lock. [registry.csv got a corrupted row under parallel workers; the G3 decision was renumbered D21 → D23 (bf2c1ac); g3_report.py was taken over by the other track (85c600c).]
13. When a fact changes, grep for and fix every copy in the same commit. [R2 patched stale probe numbers and a wrong Pacini claim; the EC count (D20d), frozen-file _status fields and the D13 fails-rule change (D27 m5) stayed stale until review.]
14. Don't reopen a logged decision without new evidence; check the decision log first. [The M4 and 1-SE disputes recurred after agreement.]
15. Time only on a quiet machine, and re-time finalists alone. [G2 fit times varied about 1.5× with shared jobs; the quiet-machine refit gave the REPORT runtimes (D25c).]
16. Ask reviewer subagents to return their report as text; the harness may refuse their file writes. [G4 and G6 reviewer writes were refused and the PI transcribed both (D26, D27).]
